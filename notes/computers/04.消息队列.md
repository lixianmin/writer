- 03 RocketMQ
  - 术语
    - 1.bid=broker id, bid=0是master
2. tag: 用于consumer过滤消息
3. key: hash索引; 命令行查看消息
    - 1. rocket的生产者和消费者都要设置group, kafka则只有消费者需要
2. 生产者: 事务消息中, 反查本地事务时, if原始生产者崩溃, 则查询同group的其它生产者
3. 消费者: 同group的消费者, clustering模式(默认)互斥, broadcasting模式并发
    - 1. 如果不使用事务消息, 是不是就不需要设置producer的group
2. rocket也可只通过不同的group消费: 分组内load balancing, 分组间fan-out
  - design pattern
    - 1. producer: sendSync+retry; 异步send会忽略retry
2. broker: 异步落盘+同步副本
 - flushDiskType=ASYNC_FLUSH: 直写PageCache, 快&安全 
 - brokerRole=SYNC_MASTER, 一主二从三副本
3. consumer: 处理幂等(version|uk); rocket无须主动提交offset
    - 1. 发送: producer用hashSelector; msg设sharding key
2. 消费: 设置orderly=true, 加锁确保queue互斥
    - 1. 缓冲: 临时大促, 等待消化
2. 分批: 增大消费者BatchMaxSize => 批量写DB
3. 有序并发: clustering消费者数 <= queue数
4. 无序并发: goroutine池+WaitGroup并发
5. 丢弃: 秒杀时, 丢弃=offset差 > 2x商品量
- 04 Kafka
  - design pattern
    - producer: 
1. 同步写+失败retry: 异步写效率不会更高, 容易丢msg
2. 每msg加uuid: 用于消费时幂等处理, 考虑sonyflake
3. acks = 1 (leader确认) / all (ISR确认)
4. 每msg按"生产者&分区"加自增id: 用于消费者检测消息丢失
    - broker: 定期落盘, ISR实时同步副本到Page Cache
1. num.partitions=12 : 限制消费并发度, 默认=1
2. min.insync.replicas=2 : 确保ISR中至少有2副本, 默认=1
3. default.replication.factor=3 : 需大于min.insync.replicas

4. unclean.leader.election.enable=false: 禁止进度落后的副本竞选为leader, 防丢消息
5. auto.leader.rebalance.enable=false: 禁止定期切leader
6. log.dirs=xxx,yyy : 配置多块磁盘, 提升读写性能, 支持failover
7. message.max.bytes=xxx 默认<1MB太小
8. auto.create.topics.enable : 防止自动创建topic
    - consumer: 
1. 幂等(msg id + uk): 同一个msg会被反复消费到
2. 数据写入db后手动commit: 自动commit会丢msg
3. 同group中: 消费者数量 == partition数量; 方便检测消息丢失
4. 设置startOffset=FirstOffset: 否则新分区的msg可能被跳过
5. 消费进度检测: 过缓则报警
6. 消费丢失检测: 生产者连续埋点, 消费者检测埋点
    - 1. producer: 选确定型路由, 比如hash balancer
2.consumer:
    - 1. 缓冲: 临时大促, 等待消化
2. 分批: min(长度, 超时) => 批量写DB
3. 有序并发: 同group消费者 <= queue数
4. 无序并发: goroutine池+WaitGroup并发
